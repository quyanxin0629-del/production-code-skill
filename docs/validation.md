# production-code Skill 验证报告

日期：2026-10-30。当前 Skill 含入口、界面元数据与 9 个按需参考文件；仓库提供可复现的验证脚本、回归测试和 CI 配置。

## 复现方式

安装 requirements-dev.txt 后，在仓库根目录执行：

```sh
python scripts/validate.py
python scripts/validate_java.py
```

Python 验证依赖仅用于维护测试，不是安装 Skill 的运行依赖。Java 验证需要 JDK 17+，从 Markdown 提取实际示例，以 --release 17 和 UTF-8 编译，临时源码与类文件退出时清理。Lua 使用 Lupa 2.6 中的 Lua 5.1 与 Redis 命令替身，不连接真实 Redis。tzdata 为没有系统 IANA 数据的环境提供时区数据。

## 本轮确认并修复的问题

1. 计时装饰器 finally 中的指标异常会覆盖成功值、业务异常或取消。现在隔离观测故障，保留业务结果，并提供有界失败计数供同事件循环健康检查读取。
2. 缓存只限制条目数，没有在哈希前限制单项输入。现在先检查列数和名称长度，再进入 LRU。
3. Lua 示例未完整拒绝非法库存编码、错误键类型和超精确整数。现在先校验参数、TYPE 与安全整数，再以原整数文本扣减。
4. inbox 的异常捕获范围过大。现在只在立即 INSERT/flush 的准确约束冲突上判重，不吞业务执行或提交错误；ack 在事务退出后执行。
5. 读重试缺少非有限预算、非法尝试数及已耗尽截止时间的入口检查。现在覆盖参数、排队、退避与取消路径。
6. Java 事务说明遗漏 Spring 6.1+ 已完成 Future 的回滚特例；并发指南补齐分段锁下容器安全、所有读写参与协议，以及锁不提供异常回滚的边界。
7. 主验证入口只加载旧批处理文件，新增测试可能漏跑；参考数也被写死。现在自动发现 test_*.py、检查引用可达性，并用新增失败用例验证检测能力。
8. 明确补入数据库读取决策：按需字段与范围、限页、批量关联 / 合适 JOIN、小型有界全集、全量流式导出；不只按 SQL 次数做选择。
9. 补入外部 URL、文件 / 归档、进程、HTML 和反序列化的按需安全边界及端口测试。
10. 验证工具显式使用 UTF-8，Java 编译指定编码，补充 tzdata 依赖及 Windows CI，避免把本机默认环境当作所有用户环境。

## 行为与故障覆盖

- 金额来源、精度、范围与分摊守恒；时区、DST gap / overlap、半小时 DST、年界转换溢出。
- JSON 重复键、非有限数值和指数溢出；严格模型、重复 SKU、数量与字段范围。
- 原异常和取消传播、上下文恢复、响应成功及失败退出、指标连续故障、缓存前校验。
- 10 万项输入的任务 / 缓冲 / 并发上界，源失败、处理失败、排队、超时和子任务自行取消。
- Lua 参数拒绝前不触碰键，错误类型 / 库存不写入，最大精确整数与不足库存；这些是解释器和命令替身测试。
- 消费提交后 ack、ack 失败重放、业务异常 / 提交异常不误判重复；这些是事务控制流替身测试。
- Java 反向多锁顺序、stripe 碰撞、部分获取失败、中断、异常退出、转账溢出前状态不变和守恒、快照一致性、Future 超时 / 取消边界。
- 未注册目的地不发请求、重定向拒绝、响应作用域、文件对象 ID 校验、租户过滤与服务端存储键。

## 仍未证明的范围

没有连接真实 MySQL、Redis、Kafka 或支付服务；Lua、事务和 HTTP 替身不证明服务器锁、隔离、故障转移或真实网络释放行为。Spring 回滚特例核对了 6.2 官方资料，未运行 Spring 应用集成。其他语言局部模式没有全部编译，不声称经过生产压测或具备全场景正确性。

结构检查、示例机制和独立试用检验的是不同层次。后续使用仍需按目标仓库版本、业务协议与部署环境选择集成验证。
