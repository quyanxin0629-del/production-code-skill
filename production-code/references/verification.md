# 风险相称的验证与交付

先阅读构建脚本和 CI，再选命令。只使用授权的本地 / 测试资源；生产迁移、真实消息和对真实下游压测不属于默认验证。

| 改动 | 有价值的证据 |
|---|---|
| 纯逻辑 | 能暴露旧缺陷的输入、边界、舍入与守恒不变量 |
| API / 序列化 | 实际 HTTP 边界，缺省 / null / 零 / 超范围，旧客户端 |
| 鉴权 / 租户 | 未认证、权限不足、跨租户、缓存与后台任务范围 |
| 数据写入 | 目标数据库条件写入、唯一冲突、回滚与提交后行为 |
| 并发 / 幂等 | 同键同时到达、独立连接或实例、失败重放、未知结果 |
| 异步 / 资源 | 取消、超时、提前终止、异常后子任务退出与资源回收 |
| MQ / 网络 | 发送成功但确认丢失、处理成功但 ack 失败、毒丸和重复 |
| 演进 | 新旧版本交叉读写、回填重入、滚动运行和回滚窗口 |
| 性能 | 目标版本 / 驱动、现实分布与并发、吞吐、尾延迟、RSS、队列与连接 |
| 低影响格式 / 文案 | diff 与已有格式命令，通常不新增测试 |

## 验证行为，不复述实现

```python
# Bad：无法发现错误业务结果
service.run(command)
mock_private_helper.assert_called_once()
# Good：观察业务结果及守恒关系
result = service.run(command)
assert result.payable_cny_fen == 288
assert result.discount_cny_fen + result.payable_cny_fen == 303
```

金额覆盖舍入、退款、上限和分摊尾差；时间用固定时钟和已知 DST 边界。并发用 event / barrier / latch 协调真实重叠，不用随机 sleep 猜测时序。独立事务和连接验证唯一成功或相同幂等结果；进程内锁测试不能证明多实例有效。

## 分层执行

1. 先运行最接近变更的编译、类型检查与现有测试。
2. 对高风险数据、协议与并发增加相关集成或故障测试。
3. 公共 API、构建和框架配置变更覆盖相关消费方和必需 CI 检查。
4. 相关检查通过后继续交付，不无目的扩大或重复；新问题再扩大范围。

SQLite 不验证 MySQL 锁、隔离与驱动游标；内存 mock 不验证 Redis Lua/cluster/故障切换；假 HTTP 不验证网络阶段超时；顺序重放不验证并发。

缺少环境时完成可运行部分，报告未执行项和原因。不把“静态看起来正确”写成测试通过，不为运行测试擅自全仓升级依赖或降低 TLS 校验。

## 性能证据

记录版本、输入规模与分布、并发、预热、连接池、机器和对照方法。先查计划、profile、分配、锁等待与队列，不用微基准推导全链路收益。

负载包含慢依赖、排队、拒绝与失败；平均延迟不代替 p95/p99。固定内存结论还需观察总行数增加时 RSS、线程、待处理任务和连接是否增长。

## 交付形式

- 实现：行为变化、不变量、实际检查结果、影响判断的限制。
- 审查：严重性、位置、触发输入或时序、影响与修复方向；不按八维凑问题。
- 教学：Bad / Good、底层机制、版本前提；业务端口明确是适配点。
- 失败：区分代码错误、环境缺失和未执行。未做生产或目标语言验证就不作对应承诺。
